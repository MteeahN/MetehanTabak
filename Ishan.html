Ishanİsim Şehir Hayvan

Ishan brings the classic pen-and-paper "Name, City, Animal" game to the browser. One player opens a room, friends join with a 5-character code, and everyone races to fill the categories with the same letter — while the game keeps the time, checks the answers and does the scoring.

Project Overview

The notebook game, now online.

Everyone in Turkey has played İsim Şehir Hayvan on the back of a notebook. Ishan keeps that exact feeling — a letter, a set of categories and a race against the clock — and removes the arguing over time and points.

Rooms hold 2 to 8 players. The host picks the number of rounds, the categories (Name, City, Animal, Plant, Object, Country and more) and the round time. Players see the same letter at the same moment, anyone who fills every category can shout STOP!, and the rest get ten seconds to finish.

The whole game is a single client file with no server code: browsers connect peer-to-peer over WebRTC and the host's tab is the referee.

Problem & Solution

Real-time, fair and Turkish to the last letter.

The Challenge
A party game only works if every player sees the same letter and the same clock, nobody can peek, and scoring disputes are settled by the game instead of by shouting.
Synchronising the letter reveal, timer and STOP! call across up to eight devices
Keeping answers hidden until the round locks, without a trusted server
Comparing answers with Turkish rules: İ/ı, case, spaces and diacritics
Validating open-ended categories fairly without a dictionary for everything
Recovering from dropped connections and host refreshes mid-match
A playful interface that still works with keyboard, screen readers and in dark mode
The Solution
A pure game engine, a host-authoritative network layer and a reviewing step where players vote on doubtful answers.
The host runs the clock and sends "time remaining"; each client derives its own local deadline
Answers stay on the host's device — others only see how many categories each player has filled
tr-TR aware normalisation, so "İzmir", "izmir" and " IZMIR " count as the same answer
Built-in lists of 81 provinces, common city aliases, world cities and countries mark answers as "Verified"
Majority objections zero out an answer; the host has the final say
Players reconnect as themselves; the host waits 20 s and can reopen the room with the same code
Development Journey

Four layers, one file, no global variables.

Phase 01
Game Rules as Pure Functions
I started by writing the rules down as a network-free, UI-free engine: building the letter pool (Ğ never appears, no letter repeats in a match), normalising answers with Turkish locale rules, and scoring — 20 points if you are the only one with a valid answer, 10 for a unique answer, 5 for a shared one.
Game Enginetr-TR NormalisationScoring Rules
Phase 02
Network Layer & Room Management
PeerJS is loaded only when a player goes online, from a pinned version with a fallback CDN. I wrote separate host and guest sessions: the host chooses the letter, runs the timer, collects answers and broadcasts state; guests reconnect automatically and keep their identity through a per-tab player ID.
PeerJS / WebRTCHost & Guest SessionsReconnection
Phase 03
Review, Objections & Statistics
After each round the reviewing screen lists every answer by category. City and Country answers are checked against built-in lists; everything else can be challenged by the other players. Finished matches are stored locally with highlights, total and round-by-round charts, and per-category statistics.
Answer ValidationVotingMatch History
Phase 04
The "Recess" Design Language
Finally I designed the look: grid notebook paper, ink outlines, highlighter accents, taped cards and hard offset shadows, with answers written in a handwriting font. In dark mode the notebook turns into a chalkboard. A small safe templating and DOM-morphing core keeps updates smooth without a framework, and focus management keeps it usable with a keyboard.
